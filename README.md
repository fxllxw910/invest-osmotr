# ИНВЕСТ-осмотр — платформа дистанционных осмотров

кабинет заказчика и кабинет исполнителя, осмотр по ссылке без установки
приложения, фотофиксация только с камеры и серверная проверка геопозиции.

## Запуск

```bash
npm start
```

Сервер поднимается на `http://127.0.0.1:4173` (порт меняется через `PORT`).
Нужен только Node.js 18+ — зависимостей нет, данные лежат в JSON-файле
(каталог меняется через `DATA_DIR`).

## Как создать новое задание

1. Войти заказчиком (`79000000000`).
2. На странице «Задания» нажать **«Назначить осмотр»**.
3. Заполнить объект, название, срок и **телефон исполнителя**.
4. Нажать «Назначить».

Что происходит дальше:

- номер задания формируется автоматически (`ИО-2026-000119` и далее);
- если такого исполнителя ещё нет, для него создаётся учётная запись
  с временным паролем;
- формируется SMS со ссылкой на осмотр, сроком и (для нового исполнителя)
  логином и паролем;
- сообщение попадает в раздел **«Исходящие SMS»** (`/outbox`).

## Придёт ли СМС на введённый номер

Отправка **выполняется по-настоящему**: сообщение уходит в SMS-шлюз и получает
квитанцию, а не остаётся в исходящих со статусом «шлюз не подключён».

Режим выбирается переменной окружения `SMS_PROVIDER`:

| `SMS_PROVIDER` | Куда уходит SMS | Что нужно |
|---|---|---|
| `smsru` | SMS.RU (`https://sms.ru/sms/send`) | `SMSRU_API_ID` |
| `smsc` | SMSC.RU (`https://smsc.ru/sys/send.php`) | `SMSC_LOGIN`, `SMSC_PASSWORD`, при желании `SMSC_SENDER` |
| `http` | свой шлюз | `SMS_GATEWAY_URL`, `SMS_GATEWAY_TOKEN` |
| `local` | встроенный шлюз `POST /api/sms/gateway` (SMS никуда не уходит) | ничего |
| `console` | stdout сервера (для отладки) | ничего |

Для боевого режима нужен `smsru` или `smsc` — сообщение реально уходит
оператору и получает квитанцию провайдера.

Параметры берутся из окружения или из файла `.env` в корне проекта
(скопируйте `.env.example`). Файл `.env` в репозиторий не попадает.

- `SMSRU_API_ID` — API-ключ SMS.RU.
- `SMSC_LOGIN` / `SMSC_PASSWORD` — доступ к SMSC.RU; `SMSC_SENDER` — имя
  отправителя, если оно согласовано.
- `SMS_GATEWAY_URL` — адрес своего шлюза, `SMS_GATEWAY_TOKEN` — общий токен;
  запросы принимаются только с заголовком `x-sms-token` (сравнение через
  `timingSafeEqual`).

Статусы сообщения: `sending` → `sent` (с номером квитанции провайдера) либо
`failed` (с текстом ошибки). В интерфейсе заказчик видит «SMS исполнителю …
доставлена в шлюз (квитанция …)», в разделе «Исходящие» — статус «доставлено».
Квитанции и журнал отправок лежат в `data/` (`smsReceipts`, `sms-outbox.log`).

Внешний шлюз принимает JSON или form-encoded тело:
`{"to": "+79514476815", "text": "…", "messageId": "…"}` → `{"ok": true, "receiptId": "…"}`.

## Почему с компьютера нельзя загрузить файл

Съёмка ведётся живой камерой через `navigator.mediaDevices.getUserMedia`,
а на телефоне дополнительно доступен системный захват
(`<input type="file" accept="image/*" capture="environment">`).
Атрибут `capture` на десктопе игнорируется по стандарту, поэтому раньше
открывался обычный выбор файла — то есть можно было подставить готовое фото.

Теперь страница шага съёмки на компьютере вообще не открывается: сервер
определяет мобильный браузер по `User-Agent`/`Sec-CH-UA-Mobile` и вместо формы
отдаёт баннер **«Пожалуйста, воспользуйтесь смартфоном»** с кнопкой возврата
к заданию и неактивными кнопками съёмки. Дополнительно это закрыто так:

1. Обработчик `change` у файлового входа отклоняет кадр с десктопного
   user-agent и требует подтверждённую геопозицию до выбора файла.
2. Сервер (`applyStep()` в `server.js`) принимает кадр только с
   `captureSource=camera`, свежим `capturedAt` (не старше 30 минут и не из
   будущего) и валидными координатами внутри радиуса. Запрос без этих полей
   возвращает 400, поэтому обойти клиент нельзя.
3. POST шага съёмки с десктопным user-agent отклоняется с кодом 403 даже при
   корректных координатах и кадре.

Текстовые шаги на компьютере доступны как обычно — блокируется только съёмка.

Пока геопозиция не подтверждена (нет GPS, доступ запрещён, точка вне радиуса
или точность хуже допустимой), кнопки «Открыть камеру» и «Зафиксировать шаг»
заблокированы.

> **HTTPS.** `getUserMedia` и точная геолокация работают только в защищённом
> контексте (`https://` или `http://localhost`). При публикации за HTTPS-прокси
> задайте `PUBLIC_URL`, чтобы ссылки в SMS были правильными. По обычному
> `http://` на телефоне живой поток недоступен — сработает системный захват
> камеры (`capture="environment"`), геоконтроль при этом сохраняется.

## Проверка осмотра заказчиком

1. Исполнитель проходит шаги и отправляет отчёт.
2. Заказчик открывает задание: у каждой фотографии есть кнопки
   **«Принять фото»** и **«Отклонить»** (с комментарием).
3. Общее решение по осмотру:
   - «Принять осмотр» доступно, когда приняты все фотографии;
   - «Отклонить осмотр» отклоняет все ещё не проверенные кадры разом.
4. Кнопка **«Скачать фото на ПК (ZIP)»** отдаёт архив: файлы вида
   `01 Общий вид (принято).jpg` и `README.txt` с координатами, точностью,
   расстоянием до объекта и комментариями.

## Кабинет исполнителя

- Видит только свои задания, не может их создавать.
- Статус каждого осмотра: в работе / на проверке / принят / отклонён.
- Раздел «Уведомления» с непрочитанными: какие фото отклонены и что переснять.
- Отклонённые поштучно кадры можно переснять, не дожидаясь общего решения:
  задание остаётся «на проверке», кнопка «Переснять» появляется только
  у отклонённых шагов, остальные фото не трогаются.
- После общего отклонения задание снова открыто для съёмки — переснимаются нужные шаги.

## Технические решения

**Только камера.** Основной путь — живой поток `getUserMedia` с камеры
устройства (на телефоне приоритет задней камеры). На мобильных как резерв
работает системный захват `capture="environment"`. Кадр уходит на сервер как
base64 из canvas (сжатие до 1600 px по длинной стороне, JPEG q=0.86) вместе с
пометкой `captureSource=camera` и временем съёмки.

**Геоконтроль на сервере.** Клиентская проверка — только UX. Решение принимает
`applyStep()` в `server.js`: координаты валидируются, расстояние считается по
формуле гаверсинуса (`lib/geo.js`), проверяются радиус и точность. Дополнительно
отклоняется кадр без `captureSource=camera` и с `capturedAt` старше 30 минут
(защита от подстановки файла из галереи). Обойти клиентскую блокировку
бесполезно.

**Метаданные кадра.** Для каждого шага сохраняются время съёмки, координаты,
точность GPS и расстояние до объекта.

**ZIP без зависимостей.** `lib/zip.js` собирает архив вручную: CRC32, локальные
и центральные заголовки, EOCD, флаг UTF-8.

**Геокодирование адреса.** При назначении осмотра координаты объекта можно
не вводить вручную: сервер ищет адрес через Nominatim (OpenStreetMap).
`lib/address.js` расшифровывает сокращения («пр-кт» → «проспект», «ул.» → «улица»),
разбирает адрес на город/улицу/дом и пробует несколько вариантов запроса.
Найденный объект принимается только если в нём совпадают город, улица и номер дома,
поэтому адрес в Челябинске не может «уехать» в другой город области.
Кнопка «Определить по адресу» в диалоге назначения делает то же самое из браузера
(`POST /api/geocode`).

## Публикация на GitHub

Репозиторий: `https://github.com/fxllxw910/invest-osmotr` (публичный).

```bash
git init
git add .
git commit -m "ИНВЕСТ-осмотр: сервис фотофиксации с геоконтролем"
git branch -M main
git remote add origin https://github.com/fxllxw910/invest-osmotr.git
git push -u origin main
```

GitHub Pages здесь не подойдёт: это Node.js-сервер с записью файлов на диск,
а Pages умеет отдавать только статику. Чтобы сайт был доступен всем, нужен
хостинг с контейнером:

- **Render** — в репозитории есть `render.yaml`; создайте Blueprint и укажите
  `PUBLIC_URL`, `SMS_PROVIDER`, `SMSRU_API_ID` в переменных окружения.
- **Docker / VPS** — `Dockerfile` в корне, данные монтируются в `/data`.
- **Fly.io / Railway** — тот же `Dockerfile`, порт из `PORT`.

Обязательно задайте `PUBLIC_URL` (например `https://invest-osmotr.onrender.com`),
иначе ссылки в SMS будут указывать на `127.0.0.1`. HTTPS нужен и для работы
камеры: `getUserMedia` и точная геолокация доступны только в защищённом
контексте.

## Тесты

```bash
npm test         # node test/run.js — поднимает свой сервер на свободном порту
npm run test:address
npm run test:sms # провайдеры SMS.RU и SMSC на локальных заглушках
npm run test:css
npm run test:all # всё подряд
```

`npm test` не трогает рабочие данные: скрипт создаёт временный каталог, стартует
`server.js` с `DATA_DIR` и `PORT` из окружения, прогоняет сценарии и удаляет каталог.
Поэтому тесты можно запускать сколько угодно раз подряд без пересоздания `data/`.

Если сервер уже запущен вручную и нужно прогнать сценарии по нему:
`BASE=http://127.0.0.1:4173 npm run test:only`.

Проверяются: вход и роли, блокировка фото вне радиуса и при плохой точности GPS,
сохранение и отдача кадра, полный цикл осмотра, назначение задания, SMS в исходящих,
поштучная проверка фотографий, запрет общего принятия при отклонённом кадре,
пересъёмка отдельного отклонённого фото без выхода из статуса «на проверке»,
ZIP-выгрузка (имена файлов, README с координатами, целостность кадров), уведомления
исполнителю, повторная съёмка после отклонения, работа по публичной ссылке без входа,
запрет чужих действий, 404 для удалённых страниц («Услуги», «Приложение», «Документы»,
соглашение), геокодирование адреса и отказ от найденного объекта в другом городе.

## Ограничения демо

- Данные хранятся в JSON-файле, без БД и миграций.
- Сессии в памяти сервера, без внешнего хранилища.
- SMS-шлюз по умолчанию локальный (см. выше); для реальных номеров нужно
  указать `SMS_PROVIDER=smsru` или `SMS_PROVIDER=smsc` и ключи провайдера.
  Пуш-уведомлений нет — только внутренние и SMS.
- Нет загрузки видео и офлайн-режима.
- Формально подлинность кадра обеспечивается только браузером и геоконтролем:
  на устройстве с подменённым браузером технически возможна подмена, поэтому
  в продакшене нужен нативный клиент с аттестацией устройства.
